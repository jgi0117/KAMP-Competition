## ① 제조 이상 정의

데이터에는 불량·고장 기록이 없고 전력·생산·기상만 있습니다. 그래서 공정 운영상의 이상을 **전력 피크(과부하)**로 정의합니다.

- 피크는 최대수요 전력요금 증가와 설비 과부하로 이어지는 운영 위험입니다.
- 지금까지 만든 전력 예측 모델을 그대로 이상 확률 모델로 확장할 수 있습니다.
- **셧다운(8/28 18시 ~ 8/29 10시, 전력 0 kW, 17시간)**은 연중 1회뿐이라 예측 대상에서 제외하고, 데이터 진단(요구사항 1번)에서 "비정상 정지"로 따로 설명합니다.

## ② 이상 기준값 177 kW

| 후보 | 값 | fold1 검증 | fold2 검증 | fold3 검증 | **Test** |
| --- | --- | --- | --- | --- | --- |
| **Test 이전 전체 상위 5% (채택)** | **177.0** | 11h (1.5%) | 66h (9.2%) | 99h (13.3%) | **49h (7.0%)** |
| Test 이전 상위 10% | 168.0 | 45h | 116h | 126h | 112h (15.9%) |
| 고정 170 | 170.0 | 35h | 103h | 117h | 99h |
| 고정 180 (구현 가이드) | 180.0 | 6h | 42h | 88h | 38h (5.4%) |

선택 이유
- Test 를 보지 않고(1/1~8/15 데이터만으로) 정한 값이라 공정합니다.
- 모든 모델·모든 구간에 **같은 숫자 하나**를 쓰므로 팀원 간 비교가 쉽습니다. 이전 코드는 구간마다 171~177 kW로 달랐습니다.
- Test 에 피크가 **49시간(연속 사건 29건, 15일)** 있어 F1 을 안정적으로 계산할 수 있습니다. 180 kW 는 38시간으로 줄어듭니다.
- 피크는 8~11시·13~14시 조업 시간, 7월·겨울철, 영업일(91%)에 몰려 있어 현장 의미가 분명합니다.

재현: `src/data_pipeline.py` 의 `peak_threshold_from_data(df)` → 177.0

## ③ 이상 확률 계산

전력 예측값만으로 경보를 울리면(예측값 ≥ 177) 피크를 많이 놓칩니다. 오차를 제곱해서 학습하는 모델은 극단값을 평균 쪽으로 낮게 예측하기 때문입니다. 그래서 **예측 오차의 크기(σ)를 감안한 확률**로 바꿉니다.

```
이상 확률 = 1 − Φ((177 − 예측값) / σ)
  Φ : 표준정규분포 누적분포함수 (scipy.stats.norm.cdf)
  σ : 검증 구간(fold 3개)에서 (실제 − 예측) 의 표준편차, 모델마다 따로 계산
예) 예측 165 kW, σ = 10 kW → 이상 확률 = 1 − Φ(1.2) ≈ 0.12
```

근거 (간이 모델로 방식 비교, 검증 fold 로 정하고 Test 에 적용)

| 방식 | Test F1 | Recall | Precision | Brier ↓ | PR-AUC |
| --- | --- | --- | --- | --- | --- |
| A. 예측값 ≥ 177 이면 경보 (확률 없음) | 0.526 | 0.408 | 0.741 | 0.051 | – |
| **B1. 오차 정규분포 확률 (채택)** | **0.558** | **0.735** | 0.450 | **0.038** | **0.666** |
| B2. 실제 오차 분포 확률 | 0.551 | 0.714 | 0.449 | 0.038 | 0.666 |
| B3. B2 + 확률 보정(isotonic) | 0.540 | 0.694 | 0.442 | 0.046 | 0.614 |
| B1 + 조건별 σ (영업일 × 조업시간대) | 0.560 | 0.714 | 0.461 | 0.038 | 0.670 |
| C. 피크 분류 모델 직접 | 0.600 | 0.735 | 0.507 | 0.045 | 0.655 |

- A 는 Test 피크의 41%만 잡지만, 같은 예측값을 B1 확률로 바꾸면 **74%**를 잡습니다.
- B1 은 확률 품질(Brier·PR-AUC)이 가장 좋고, 전력 예측 모델 하나로 kW 예측과 이상 확률을 함께 냅니다.
- 확률 보정과 조건별 σ 는 검증에서만 좋아지고 Test 에서는 이득이 없어 채택하지 않았습니다. 요구사항 5번(창의성) 장표에 "시도하고 검증한 방법"으로 씁니다.
- C(분류 모델)는 F1 이 조금 높지만 모델을 따로 만들어야 하고 확률 보정이 나쁩니다(검증 최적 경보 기준이 0.05). 앙상블·비교 후보로 남깁니다.

## ④ 경보 기준과 평가 지표

- **경보 = 이상 확률 ≥ 경보 기준.** 경보 기준은 **검증 구간에서 F1 이 가장 높은 확률**(0.05 단위, 동점이면 낮은 값)로 모델마다 정하고, Test 에는 그 값을 그대로 씁니다.
- **대표 지표: F1** (요구사항 그대로). 보조: **Recall**(피크를 놓치지 않는 비율, FN 이 더 위험), Precision, **Brier**(확률 정확도), **PR-AUC**(경보 기준과 무관한 탐지력).
- 전력 예측 지표 **MSE·RMSE·R²·MAE** 도 함께 보고합니다.
- FN = 실제 피크인데 경보 없음(놓침), FP = 경보했는데 피크 아님(헛경보). 요구사항 3번 오류 분석에 사용합니다.

## 팀원별 적용 방법

**딥러닝 (lhs)** — `final_evaluate.py` 에 모두 구현되어 있습니다. 실행하면 베이스라인 2개와 LSTM·TCN·Weighted Ensemble·TCN-LSTM 이 한 표로 나옵니다.

**트리 모델·기타 모델** — 아래 순서로 같은 숫자를 낼 수 있습니다.

```python
import numpy as np
from scipy.stats import norm
from sklearn.metrics import f1_score

THR = 177.0
# 1) 검증 구간(5/16~8/15, fold 별 학습) 예측값 pred_val, 실제 y_val  → σ, 경보 기준
sigma = np.std(y_val - pred_val, ddof=1)
prob_val = 1 - norm.cdf((THR - pred_val) / sigma)
grid = np.round(np.arange(0.05, 0.951, 0.05), 2)
cutoff = grid[np.argmax([f1_score(y_val >= THR, prob_val >= c) for c in grid])]
# 2) Test(8/16~9/14, 셧다운 제외) 예측값 pred_test → 확률·경보·F1
prob_test = 1 - norm.cdf((THR - pred_test) / sigma)
f1 = f1_score(y_test >= THR, prob_test >= cutoff)
```
